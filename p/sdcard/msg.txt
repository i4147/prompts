Write a Python module that implements a small length-prefixed JSON messaging protocol over raw
TCP/Unix sockets, optionally supporting Unix file descriptor passing.
Requirements: - Use the standard library only:
`json.loads`, `array`, `socket`,
and `typing` (`Any`, `Tuple`, `Optional`). - Implement a function
`read_msg(s: socket.socket) -> Any` that:
- Reads exactly 4 bytes from the socket first
(looping on `recv` until all 4 bytes are received,
since a single `recv` call may return fewer bytes than requested). - Interprets those 4 bytes as a
big-endian unsigned integer representing the length of the upcoming payload. - Reads exactly that
many bytes from the socket (again looping until the full payload is received). - Decodes the payload
as UTF-8 and parses it as JSON using `json.loads`,
returning the resulting Python object. - Implement a function `send_msg(c: socket.socket, msg: str)`
that: - Encodes the given string message as UTF-8 bytes. - Sends the 4-byte big-endian length prefix
of the encoded message using `sendall`. - Sends the encoded message bytes using `sendall`. -
Implement a function `send_read_msg(s: socket.socket, msg: str) -> Any` that:
- Sends a message using `send_msg`. - Immediately waits for
and returns the response using `read_msg`. - Implement a function
`read_msg_fd(s: socket.socket) -> Tuple[Any, Optional[int]]` that:
- Performs the same length-prefixed read and JSON-decode logic as `read_msg`,
but reads the payload using `socket.recvmsg` instead of `recv`,
in order to also receive ancillary data. - Uses an `array.array("i")` buffer to collect any file
descriptors sent via `SCM_RIGHTS` control messages (`socket.SOL_SOCKET` / `socket.SCM_RIGHTS`),
appending received control-message bytes into this array
(trimming to a multiple of the array's item size). - Loops `recvmsg` calls
until the full payload length has been read,
accumulating both the payload bytes
and any received file descriptors. - Returns a tuple of the parsed JSON object
and the first received file descriptor as an `int`, or `None` if no file descriptor was received.
Notes on behavior: - All reads must loop until the full expected number of bytes has been received,
since sockets can return partial data on a single call. - The length prefix is always 4 bytes,
big-endian, unsigned. - The payload is always UTF-8 encoded JSON text. - `read_msg_fd` is meant to
support passing an open file descriptor (e.g., for inter-process socket/file handoff) alongside a
JSON message over a Unix domain socket,
using the SCM_RIGHTS ancillary data mechanism. - No error handling, logging,
or additional functionality should be added beyond what's described;
keep the implementation minimal
and directly focused on this length-prefixed JSON (and optional fd) messaging protocol. ---
