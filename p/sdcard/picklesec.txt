Helpers for safer and/or more explicit pickle usage in NLTK. - RestrictedUnpickler:
blocks unpickling of *any* globals (classes/functions).
Intended for loading NLTK data packages where we control the serialization. - WarningUnpickler:
emits a security warning before unpickling (does not make unpickling safe). - AllowlistUnpickler:
only reconstructs an explicit, audited allowlist of globals.
Use it for loading objects
whose set of legitimate classes is known (e.g. a trained model) so that arbitrary-code gadgets such
as ``os.system`` can never be reconstructed from an untrusted file.
