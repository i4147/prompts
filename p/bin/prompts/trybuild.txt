Write a Python script that acts as a parallel project test runner:
given a root directory,
it recursively discovers Python project folders
(identified by common project marker files such as setup or pyproject configuration files),
skips common non-source and tooling directories like version control folders, virtual environments,
caches, and build outputs,
and then executes each discovered project's test suite concurrently using a fixed pool of
worker processes.
Each project should be tested in an isolated,
temporary environment so that its dependencies
and any side effects do not interfere with other projects or the host system.
The script should accept command-line options for the root path to scan,
the number of parallel workers, a per-project timeout after which a test run is forcibly terminated,
and an optional filter to limit which projects are tested.
For each project, it should record the outcome (passed, failed, skipped, timed out, or errored),
the elapsed time, a short reason when it does not pass,
and the last several dozen lines of combined test output for diagnostics.
Handle interruption signals gracefully by stopping outstanding work and cleaning up child processes
and temporary resources.
Use structured, leveled logging to report progress as each project finishes,
and print a final summary table with totals per outcome, overall duration,
and a clear non-zero exit code if any project failed or errored.
The script should degrade gracefully when optional TOML parsing support is unavailable,
and must be robust against permission errors
or unreadable directories encountered during discovery. ---
