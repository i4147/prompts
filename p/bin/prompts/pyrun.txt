Write a Python command-line tool that checks a set of Python source files for runtime import
and execution health,
running each file in an isolated subprocess in parallel and producing a categorized summary report.
The tool should accept one or more file paths
or a directory to scan (recursively discovering Python files),
along with optional settings for the number of concurrent workers and a per-file timeout in seconds.
For each file, it should execute the script in a separate process,
capture its exit status and error output, and measure how long it took to run.
It must handle files that exceed the timeout by reporting them as timed out,
and treat user interruption gracefully so that partial results are still reported.
Classify each file's outcome into a fixed set of categories based on the error type found in the
captured stderr: success, module not found, import error, syntax error, attribute error, type error,
value error, keyboard interrupt, timeout, or other error.
Truncate long error messages to a sensible maximum length for display.
After all files have been processed,
produce a summary that reports the total number of files checked, how many succeeded,
how many failed, and a breakdown of failures by category,
along with the duration of each file's run.
Output the report to the console in a readable, aligned format,
and optionally write it to a file in a structured format such as JSON or CSV.
Use a proper exit code: zero when all files pass, and a non-zero code when any file fails.
Use structured logging for progress and diagnostics, keep the output clean for end users,
and make the tool robust to unreadable files, missing paths,
and invalid arguments with clear error messages. ---
