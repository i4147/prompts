Write a Python script that acts as a bulk file and directory renaming utility.
The tool should take one or more starting paths (defaulting to the current working directory)
and recursively traverse them to find files and folders
whose names need to be transformed according to user-specified rules.
The script should be driven by command-line options that let the user control the behavior:
whether to process files, directories, or both; whether to descend into subdirectories and how deep;
whether hidden items and symbolic links are included;
and which directory names to exclude from traversal using glob-style patterns.
It should support multiple renaming transformations that can be applied to names,
such as replacing text or patterns with a substitution, changing letter case,
stripping or normalizing whitespace and special characters, sanitizing names for filesystem safety,
removing accents or converting to ASCII,
and applying numbering or timestamps with a configurable format and a random or sequential mode.
Transformations should be combinable and applied in a predictable order,
operating only on the file or folder name itself rather than its full path,
and preserving file extensions when requested.
The tool should operate in a safe-by-default manner:
provide a dry-run or preview mode that shows every planned rename without modifying anything,
and require an explicit flag to perform actual changes.
It should detect and avoid name collisions within the same directory,
either by skipping conflicting renames, appending unique suffixes, or reporting them,
and it should never overwrite existing items.
Renames of directories should be handled so that the traversal remains correct
and nested items are still processed reliably.
Output should include a clear console summary for each planned or completed rename,
along with counts of processed, renamed, skipped, and failed items.
The script should also support writing a detailed log of all operations to a file in a structured
format (such as JSON) so that actions can be reviewed or reversed later.
Errors such as permission problems
or invalid names should be reported clearly without stopping the entire run,
and the script should exit with a meaningful status code reflecting success, partial failure,
or invalid arguments. ---
