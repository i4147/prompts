Write a Python script that acts as a lightweight build-and-package tool for a Rust project that
exposes a Python extension module.
The script should read the project's manifest file in the current directory to determine the package
name and version, normalizing the name so it is valid as a Python module identifier,
and fail with a clear error message and non-zero exit status if the name cannot be determined.
The script should compile the Rust project into a native shared library for the current Python
interpreter and platform, then package the result as a standards-compliant Python wheel file.
It should determine the appropriate wheel compatibility tags automatically from the running
interpreter, including the Python version, the free-threaded build variant when applicable, the ABI,
and the operating system and CPU architecture,
with sensible handling for less common platforms such as ARM variants on Linux.
The packaging step should copy the compiled library into a package directory,
generate the required metadata files
(package metadata, wheel metadata,
and a record file listing every included file with its SHA-256 hash
and size encoded in the standard format),
and assemble everything into a single zip archive with a `.whl` extension placed in an
output directory.
The output filename should follow the standard wheel naming convention derived from the package
name, version, and computed tags.
The script should provide clear console progress messages prefixed with status markers,
clean up temporary build artifacts, and report the final path of the generated wheel on success.
It should handle errors from the compilation subprocess by surfacing the failure
and exiting with a non-zero status.
Optionally, it should accept command-line arguments to control behaviors such as build mode
(debug or release), the output directory,
and whether to install the resulting wheel into the current environment afterward. ---
