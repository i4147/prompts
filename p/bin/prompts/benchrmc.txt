Write a Python script that scans a given directory (or the current working directory by default) for
Python source files, and then strips or simplifies their content in a bulk, parallel fashion.
The tool should accept an optional path argument from the command line
and an optional setting for the number of concurrent workers,
defaulting to a sensible value based on the available CPU cores (capped at 8).
If no Python files are found at the given location, it should exit with a clear error message.
The script should work with a set of transformation options that aggressively reduce the code:
removing all comments, docstrings, and type annotations, collapsing excess blank lines,
while leaving commented-out code untouched.
The transformations must be performed on temporary working copies of each file so that the
processing is safe and isolated,
with the results written out in a way that keeps the process reliable and avoids leaving partial
or corrupted output behind.
Backups should not be created, and the tool should operate in live (non-dry-run) mode by default.
Key behaviors to satisfy:
- Discover all Python files recursively under the provided path. - Copy each source file into a
temporary workspace before processing, using unique,
collision-free names. - Apply the configured minification-style transformations to each file,
handling syntax errors
or unreadable files gracefully without stopping the whole batch. - Run the work concurrently across
files using the requested number of workers. - Report progress
and a final summary (files processed, succeeded, failed, and elapsed time). - Clean up all temporary
resources automatically when finished, even if errors occur. ---
