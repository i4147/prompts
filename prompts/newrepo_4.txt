Write a Python script that automates publishing a local project folder to a new
GitHub repository.
The tool should accept a path to a local directory and a desired repository name
(with optional flags for visibility, description, branch name, and an initial
commit message), then carry out the full workflow: initialize a local git
repository if one doesn't already exist, stage and commit the existing files
with a sensible default commit message, create the remote repository on GitHub
through its REST API using a personal access token, add that remote as origin,
and push the branch to it.
The tool should load credentials from a user-level environment file in the home
directory, with a clear fallback to an environment variable, and it should fail
with a helpful message if no token is available.
It should validate inputs before doing any work, such as confirming the target
directory exists and that the repository name follows GitHub's naming rules, and
it should detect and handle common conflicts gracefully, for example when a
repository with the same name already exists or when the local folder already
has a remote configured.
Network-facing operations should be resilient: requests to the GitHub API should
retry transient failures and rate-limit responses with backoff, and calls should
respect reasonable timeouts.
Local git commands should also be time-limited so the tool never hangs
indefinitely.
Errors from any step should be reported clearly to the user with a non-zero exit
status, and the tool should avoid leaving the repository in a confusing
half-configured state where practical.
Logging should be configurable through an environment variable, defaulting to
informational messages that tell the user each major step as it happens
(validating, initializing, committing, creating the remote, pushing), with more
detail available at debug level.
Sensitive values such as the access token must never be printed or written to
logs.
The script should be runnable from the command line with clear help text
describing every option, and it should print a concise summary at the end
showing the new repository's URL on success.
Keep the design modular and readable so it can be easily extended, for example
to support organization-owned repositories or additional hosting providers. ---
